libs/sha.jar is not part of the Nostalgia sources, so it has to be supplied.

Option A (manual, recommended):
1. Take the patched sha.jar (built from Crown91/sha_test, artifact sha-mod-jar).
2. Add file -> Upload files in this repository, name it exactly libs/sha.jar.
Binary files can only be added this way (or with git) -- the GitHub API used by
assistants accepts text content only.

Option B (automatic):
1. Create a fine-grained PAT with Actions: read + Contents: read on Crown91/sha_test.
2. Add it here as the repository secret SHA_TEST_TOKEN
   (Settings -> Secrets and variables -> Actions).
The build-jar workflow then downloads the sha-mod-jar artifact from the latest
successful sha_test build and uses it as libs/sha.jar automatically.

The correct (patched) jar contains assets/sha/bin/android-arm64/sha_rapier.so --
an aarch64 ELF native library. The original jar shipped only x86_64/Windows
natives, which caused:
  UnsatisfiedLinkError: ... is for EM_X86_64 (62) instead of EM_AARCH64 (183)

sodium.jar, punchy.jar and zemlya-1.0.0.jar already ship with the sources.
